## v12.2.0 — AI in the live terminal

Today neither the built-in assistant nor MCP apps can see the user's live terminal or act in it: they run commands on a separate SSH exec channel. This version brings AI help *inside* the terminal the user works in, opt-in and through the same permission engine.

1. **Share this terminal with AI** (per terminal window, off by default): a toggle in the terminal's title bar / AI menu and a coloured "AI can see this terminal" badge while it is on. The AI may read the last N lines of the screen and scrollback (policy `ai_terminal_context_lines`, default 200, hard cap), the current directory (OSC 7 or the v11.7.0 lookup) and the last command with its output (OSC 133 shell integration markers, else heuristics). The context is redacted before it leaves WRM and framed as untrusted data. Turning it on or off is audited; it ends with the window or the session. Policy `ai_terminal_share` (who may share) with per tag / folder / connection / host rules (`ai_terminal_share_rules`); the most restrictive rule wins.
2. **Run in my terminal:** a tool `terminal_run` (built-in panel and MCP, scope `terminal_with_approval`) types a command into the user's visible terminal instead of the hidden exec channel, through the same permission engine (read-only: classifier-approved commands only; ask: an approval card with Edit; automatic: the allow list only; the destructive blocklist always). It never types into a password prompt, a full-screen program (alternate screen) or a non-shell context. The output returned to the model is captured until the prompt returns (OSC 133) or a timeout, redacted and size-capped. A tool `terminal_read` returns the shared context (scope `terminal_read`).
3. **Attach an MCP app to this terminal:** "Connect to AI app…" lists the user's active AI connections; picking one binds that connection's sessions to the terminal window (turning on sharing for it). `list_connections` / `open_session` show attached terminals. Detach and revoke take one click; the binding never outlives the window or the token.
4. **Ask AI about a selection:** right-click a selection → "Ask AI" (explain this error, suggest a fix, …); the selection is sent redacted to the built-in panel, or to an attached MCP app as a pending context item it can fetch.
5. **Quick access:** Ctrl+Shift+A opens the AI panel for the focused terminal with sharing offered; a copyable bash / zsh shell integration snippet (OSC 7 + OSC 133), optional, explained in the README.

Tests (fake providers, the MCP client harness, the test SSH host): share off ⇒ no context reachable; redaction and the line cap; `terminal_run` refused in the alternate screen and at a password prompt; approve / deny / edit; the read-only classifier and the destructive block via `terminal_run`; attach / detach / revoke and expiry; prompt injection in terminal output not changing mode or scopes; audit entries; policies (most restrictive wins). Playwright: the share badge, the approval card in the terminal, the context menu, Croatian, 390 px. SECURITY.md: the threat model of sharing a live terminal with AI and of typing into it.
